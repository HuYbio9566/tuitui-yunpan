# 知识库垂直场景 Agent × 云盘：需求探索研究框架

> 研究类型：前期需求探索（不是立项方案、PRD 或技术设计）  
> 日期：2026-08-14  
> 关联项目：推推-云盘工具项目  
> 使用方式：先用于访谈、场景筛选和概念原型；证据充分后再进入 MVP 决策

## 1. 研究任务

探索一个问题：**当企业文件已经沉淀在云盘中时，哪些垂直工作场景值得由“知识库 + Agent”持续完成，并且可以发展为云盘内置能力、独立工作台或可连接其他系统的产品？**

本研究必须回答：

1. 谁在什么工作时刻遇到什么高成本问题？
2. 这个问题为什么需要持续知识，而不是普通搜索、问答或单次 AI 工具？
3. Agent 要读取哪些云盘内容、执行哪些动作、把结果回存到哪里？
4. 哪些环节必须人工确认，哪些环节可以自动化？
5. 用户会选择哪种产品形态，购买人和使用人分别是谁？
6. 用什么低成本证据决定继续、调整或停止？

## 2. 研究对象清单

| 研究对象 | 典型知识源 | Agent 工作结果 | 与云盘的关键关系 | 初始优先级 |
|---|---|---|---|---|
| 财务票据/报销核验 Agent | 报销制度、发票、供应商和项目名单 | 通过/异常/缺件清单、复核报告 | 受控文件夹、权限、原件引用、结果回存 | A |
| 合同审阅与版本风险 Agent | 合同模板、条款库、授权矩阵、历史版本 | 风险标注、条款引用、谈判问题 | 版本链、批注、审阅历史和权限 | A |
| 投标/售前材料组装 Agent | 产品资料、案例、资质、历史标书 | 针对客户的材料包和缺件清单 | 按项目文件夹取材、引用版本、导出归档 | B |
| 项目交付/验收 Agent | 交付清单、验收标准、会议纪要 | 里程碑状态、缺件和验收风险 | 文件夹状态、任务通知、审计记录 | B |
| HR 制度与入职 Agent | 制度、地区规则、岗位和员工资料 | 有效版本答复、入职清单 | 生效日期、身份权限、敏感资料隔离 | B |
| 教学/培训备课 Agent | 课件、题库、教案、学情资料 | 教案、练习、复盘和版本化课程包 | 课程库、模板复用、结果回存 | B |
| 文件夹经营摘要 Agent | 报告、台账、项目材料 | 周期摘要、异常趋势、决策问题 | 文件夹范围、定时运行、引用原文 | C |

优先级不是市场结论，而是第一轮访谈的抽样顺序。判断场景时使用：

> 场景机会分 = 任务频次 × 文件依赖度 × 规则稳定度 × 错误可控度 × 闭环价值 ÷ 接入复杂度

## 3. 需求探索因素（每个场景都必须填写）

### A. 用户与触发

- 主要使用人、复核人、规则负责人、购买决策人是谁？
- 任务由什么事件触发：文件进入文件夹、版本更新、周期到期、人员入职，还是人工发起？
- 当前每周/每月发生多少次，单次涉及多少文件？

### B. 现状与痛点

- 用户现在如何找文件、判断、协作、审批、归档？
- 哪一步最耗时，哪一步最容易错，哪一步最难追责？
- 现有云盘、OA、ERP 或人工表格为什么没有解决？

### C. 知识边界

- 必须使用哪些文件夹、文件类型、版本和生效日期？
- 知识冲突、缺失、过期或无权限时，系统如何停止并请求人工确认？
- 用户是否愿意指定并维护知识负责人？维护成本是多少？

### D. Agent 行为与工作流

- Agent 只回答问题，还是要批量读取、分类、判断、生成、通知和回存？
- 每个动作的输入、输出、可撤销性和失败状态是什么？
- 哪些结论必须展示原文引用、规则依据、置信度和待确认项？

### E. 云盘合作价值

- 云盘在该场景中是入口、可信知识底座、执行空间、结果归档，还是权限/审计基础？
- 必须调用哪些能力：文件读取、版本、元数据、权限校验、变更监听、评论、任务通知、回存？
- 如果脱离云盘成为独立产品，用户是否仍会使用？独立形态新增了什么专业能力？

### F. 价值与证据

- 价值是节省处理时间、减少错误、提升合规、缩短交付，还是减少专家重复答疑？
- 成功指标能否在 2–4 周内测量？
- 用户是否愿意提供脱敏样本、真实复核人和预算信息？

### G. 风险与边界

- 财务、法务、人事等高风险结论是否明确定位为初审建议？
- 是否存在越权读取、错误引用、版本错用、敏感数据外泄或结果覆盖原件的风险？
- 是否有人工兜底、审计日志、保留期限和数据不出域要求？

## 4. 三种产品形态假设

| 形态 | 核心体验 | 适合验证的问题 | 主要代价 |
|---|---|---|---|
| 云盘内置入口 | 在文件夹/文件详情页发起任务、看引用和回存结果 | 用户是否愿意在原工作位置使用 Agent | 受云盘交互和发布节奏限制 |
| 独立垂直工作台 | 任务队列、规则配置、批处理、复核和审计 | 专业工作流是否足以形成独立产品 | 需要单独登录、授权和产品心智 |
| 连接器/API | 接入财务、法务、OA、ERP 等系统 | 是否能进入核心业务流程并产生预算 | 集成成本高、销售周期长 |

当前建议验证顺序：**云盘内置入口（发现与回存）→ 独立垂直工作台（批处理与复核）→ API/连接器（系统级自动化）**。这是研究假设，必须用访谈和概念测试验证。

## 5. 首轮概念需求（以票据/合同为例）

### 最小闭环

1. 用户选择一个受控文件夹并确认权限范围。
2. 绑定制度/规则、模板、名单等知识源，并显示版本和生效日期。
3. Agent 批量处理文件，任务状态可见：处理中、待复核、失败、已完成、已回存。
4. 每条结论展示结论、证据引用、规则依据、置信度和缺失信息。
5. 用户可以确认、驳回、补充材料或转交负责人。
6. 生成报告/批注/复核清单并回存云盘，原件不被覆盖。

### 必须验证的体验

- 看不到文件时，用户能理解是权限限制还是没有匹配内容。
- 找不到依据时，Agent 明确说“暂无依据”，不会编造确定结论。
- 版本冲突时，系统暂停相关结论并要求选择有效版本。
- 回存后能从报告跳回原文件、原页和原版本。

## 6. 研究方法与产出

### 访谈（6–8 人）

覆盖财务/法务/知识负责人/IT 管理员/业务负责人；每人重点追问最近一次真实任务，不询问“你想不想要一个 AI”。

### 文件包走查（3 类）

收集脱敏的票据、合同、制度或项目交付文件包，记录文件数量、版本、权限、规则来源、人工判断和回存方式。

### 概念测试（3 个）

测试批量异常队列、证据化合同审阅、有效版本制度问答。对比聊天式入口和任务式入口，观察完成时间、复核采纳率和信任原因。

### 研究产出

- 场景卡：用户、触发、文件包、现状流程、痛点、Agent 动作、云盘接口、人工边界。
- 需求证据表：观察事实、用户原话、频次/时长、风险、证据强度。
- 概念原型反馈：理解度、可信度、可控感、愿意试用程度。
- 决策页：继续 / 调整 / 停止，以及下一轮 MVP 范围。

## 7. 首轮假设与通过标准

| 假设 | 验证方式 | 建议通过标准 |
|---|---|---|
| 受控文件夹比单次上传更贴近真实任务 | 文件包走查+概念测试 | 8/10 目标用户能独立发起任务 |
| 证据引用比更流畅的聊天更能建立信任 | 两版原型对比 | 带引用版本复核采纳率更高 |
| 异常队列比聊天窗口更能推动完成 | 任务流测试 | 完成一个批次的时间更短 |
| 结果回存是闭环而非附加功能 | 试点观察 | 超过半数任务会回存或归档 |
| 规则负责人愿意维护知识源 | 配置任务观察 | 30 分钟内完成首个规则集 |
| 场景价值足以支持独立产品 | 价值访谈 | 找到明确购买人、预算来源和复购触发 |

## 8. 当前阶段的决策门槛

只有同时满足以下条件，才建议进入 MVP：

- 有明确高频任务，而非泛泛“想用 AI”；
- 文件、规则和结果都能在授权范围内闭环；
- 至少一个真实组织愿意提供脱敏样本和复核人；
- 高风险结论有人工确认和审计路径；
- 价值可以用时长、错误、复核轮次或回存率衡量；
- 独立产品形态相对云盘内置能力有清晰增量。

如果只证明了“回答看起来不错”，不进入 MVP。
