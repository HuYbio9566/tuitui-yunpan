Research map · 需求探索

让云盘里的文件，开始完成工作。

这不是一个“能回答所有问题”的知识库，而是一套围绕高频、强规则、需要留痕的文件工作流 Agent。云盘提供可信上下文，Agent 把它变成可复核、可执行的工作结果。

7 个候选场景3 种产品形态10 个验证假设4 周研究周期
首个试点建议

财务票据 / 合同合规核验 Agent

从受控文件夹取数，按企业规则核验，给出逐条结论与引用，发起人工复核，生成报告并回存云盘。

01 / 先看判断

先证明闭环，
再证明平台。

首期不追求覆盖所有知识问答，优先验证一个真实任务是否能完成“读取 → 判断 → 复核 → 回存”。

01

文件是上下文

权限、版本、组织关系和历史记录，让 Agent 的结论有边界、有来源。

02

队列比聊天更接近工作

批量任务、异常分级和人工复核，比一次性问答更能推动事情完成。

03

高风险场景不自动拍板

财务、法务等场景定位为初审与协作，关键判断必须有引用和人工确认。

候选垂直场景 7 items

知识源

报销制度、发票、供应商和项目名单。

Agent 结果

抽取字段、规则校验、重复/缺失/异常识别、复核报告。

云盘关系 / 风险

受控文件夹、原件引用、结果回存；注意 OCR 质量与税务边界。

知识源

合同模板、条款库、授权矩阵和历史谈判版本。

Agent 结果

识别类型、按清单审阅、比较版本、标注风险、生成问题。

云盘关系 / 风险

版本链、共享权限、批注关联；不可把建议表述成法律结论。

知识源

产品资料、案例、资质、历史标书和客户行业信息。

Agent 结果

按客户场景组装材料包，标记旧版本与缺件。

云盘关系 / 风险

按项目文件夹取材并归档；需防止引用过期版本。

知识源

交付清单、验收标准、会议纪要和里程碑资料。

Agent 结果

检查缺件、里程碑状态和验收风险，发起补件任务。

云盘关系 / 风险

文件夹状态、任务通知、审计记录；需要跨角色协作。

知识源

制度、地区规则、岗位和员工资料。

Agent 结果

按身份和生效日期回答制度，生成入职清单。

云盘关系 / 风险

敏感资料隔离、版本生效管理；需明确适用范围。

知识源

课件、题库、教案和学情资料。

Agent 结果

生成教案、练习、复盘和可复用课程包。

云盘关系 / 风险

课程库、模板复用、结果回存；需区分生效教材版本。

知识源

报告、台账、项目材料和周期性文档。

Agent 结果

生成带引用的摘要、异常趋势和待决策问题。

云盘关系 / 风险

按范围定时运行并回存；单独付费差异化较弱。

03 / Product form

云盘入口，
专业工作台。

推荐组合不是二选一：云盘负责发现、授权和回存；独立工作台负责批量任务、规则配置、复核和审计。

01入口

云盘内置 Agent

在文件夹或文件详情页直接使用。上手快，权限和回存天然闭环；适合作为主入口。

02推荐组合

独立垂直工作台

承载队列、规则、批处理、复核和审计。专业能力足够强时，可形成独立产品形态。

03二期

连接器 / API

接入财务、法务、OA、ERP。进入核心流程，客单价高，但集成成本和销售周期也更高。

04 / Minimum loop

一个任务，
六个可观察节点。

每一步都应该有输入、输出、失败状态和人工边界。可观察性比“模型看起来很聪明”更重要。

01选定范围选择受控文件夹，确认权限。
02绑定知识制度、模板、名单；显示生效日期。
03批量分析处理中、失败、待复核状态可见。
04证据化结果结论、引用、依据、置信度、缺失项。
05人工复核确认、驳回、补件或转交负责人。
06回存归档报告和批注回存，原件不覆盖。
05 / Research lens

需求探索的
七个镜头。

每个候选场景都必须回答这些问题，避免被“模型能力展示”带偏。

01

用户与触发

谁使用、谁复核、谁维护规则、谁购买？任务由什么事件触发？

02

现状与痛点

当前如何找文件、判断、协作、审批、归档？最耗时和最难追责的步骤是什么？

03

知识边界

哪些文件夹、类型、版本和生效日期是有效依据？冲突或无权限时如何停止？

04

Agent 行为

只回答，还是要批量读取、分类、判断、生成、通知和回存？每个动作如何撤销？

05

云盘合作价值

云盘是入口、知识底座、执行空间、结果归档，还是权限与审计基础？

06

价值与证据

价值是节省时间、减少错误、提升合规、缩短交付，还是减少专家答疑？怎么测量？

07

风险与边界

如何处理越权、错引、版本错用、敏感数据外泄和高风险结论的人工兜底？

08

独立形态增量

如果脱离云盘成为独立产品，新增的队列、规则、复核和审计能力是否值得付费？

06 / Evidence

先验证信任，
再验证效率。

4 周内用访谈、脱敏文件包和概念测试，把“感觉有价值”变成可判断的证据。

H1

受控文件夹比单次上传更贴近真实任务

验证：文件包走查 + 概念测试。通过：8/10 目标用户能独立发起任务。
H2

证据引用比更流畅的聊天更能建立信任

验证：两版原型对比。通过：带引用版本复核采纳率更高。
H3

异常队列比聊天窗口更能推动完成

验证：任务流测试。通过：完成一个批次的时间更短。
H4

规则负责人愿意维护知识源

验证：配置任务观察。通过：30 分钟内完成首个规则集。
H5

云盘权限是购买理由，而非技术细节

验证：管理员与销售访谈。通过：至少 3 个客户主动提及权限或审计。
H6

高风险结论的错误边界可接受

验证：双人复核 + 误报漏报记录。通过：高风险结论零无引用输出。
H7

结果回存能形成闭环

验证：试点任务追踪。通过：超过半数任务完成回存或归档。
H8

专业工作台值得独立存在

验证：观察高频批处理。通过：每周至少 2 次批量任务。
H9

用户愿意为节省的复核时间付费

验证：价值访谈 / 概念报价。通过：找到预算来源和采购人。
H10

场景可从单部门复制到相邻部门

验证：多部门试点。通过：规则复用率和扩展意愿达到预设目标。
07 / Decision gate

什么时候，
才进入 MVP？

如果只证明了“回答看起来不错”，不进入 MVP。

继续的最低证据

一个高频任务，能在授权范围内闭环。

不是模型回答得多漂亮，而是一个真实组织愿意提供样本、复核人和预算，并且结果能被测量、被回存、被追责。

✓有明确高频任务，而非泛泛“想用 AI”。
✓文件、规则和结果都能在授权范围内闭环。
✓至少一个组织愿意提供脱敏样本和复核人。
✓高风险结论有人工确认和审计路径。
✓价值可用时长、错误、复核轮次或回存率衡量。
✓独立产品形态有清晰的能力增量。

下一步 4 件事

  1. 在票据核验和合同审阅中选 1 个首试点。
  2. 找到 1 个愿意提供脱敏样本的组织。
  3. 只测试受控文件夹、引用、异常队列、人工确认、回存。
  4. 用复核时间、采纳率、回存率做继续 / 调整 / 停止决策。
