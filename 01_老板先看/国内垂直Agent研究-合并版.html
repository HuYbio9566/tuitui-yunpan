04 / 用户与任务

购买人、规则人、执行人不是同一个人

产品需要同时解决 ROI、规则准确性、操作效率与系统治理。

预算 / 决策人CFO、法务负责人、销售 VP、厂长
要：ROI、风险、可控交付
→
规则负责人财务、法务、投研、医疗、工艺专家
要：规则版本、证据、人工覆盖
→
高频执行人审核、销售、采购、分析师、工程师
要：少录入、少查找、少切系统
→
系统 / 合规人IT、数据、审计、安全负责人
要：权限、日志、接口、部署边界

七类核心任务的共同骨架

行业触发Agent 核心动作交付物人工关口
财务票据 / 报销包到达抽取、验真、制度匹配、异常分级通过项 + 异常证据包重大金额、税务与付款
外贸采购需求或新询盘研究、筛选、跨语种生成、跟进供应商短名单 / 商机下一步交易条件与对外承诺
销售会议 / 客户行为总结、识别意图、推荐动作、回写纪要、任务、CRM 状态报价、承诺与关键关系
医疗症状 / 报告 / 随访知识检索、风险分层、解释与导航证据化解释 / 就医建议诊断、处方与急重症

05 / Agent 能力模型

五层能力决定是不是 Agent

上层越强，越依赖下层的可信数据、权限和行业规则。

L1 · 可信上下文权限、版本、对象关系、时效、来源
L2 · 领域模型术语、规则、指标、SOP、企业 playbook
L3 · 规划与判断拆解任务、验证前提、选择工具、处理异常
L4 · 工具与动作检索、抽取、计算、触达、审批、系统回写
L5 · 治理与学习人工复核、证据链、权限拦截、反馈优化

08 / 云盘合作

云盘做可信控制层，Agent 做专业任务层

合作的关键不是“接一个聊天框”，而是让文件包成为可触发、可复核、可回存的任务对象。

云盘 · 控制层

可信上下文

  • 文件包 / 版本 / 关联关系
  • 组织权限与外链边界
  • 原文定位与证据快照
  • 任务状态与结果回存
⇄
垂直 Agent · 专业层

理解、规划、判断

  • 行业对象与术语解析
  • 企业规则 / SOP 匹配
  • 多步工具调用与异常分级
  • 置信度、人工复核与学习
⇄
业务系统 · 执行层

最终动作

  • ERP / 费控：凭证、付款
  • CRM：商机、任务、触达
  • CLM：审批、签署、履约
  • MES / HIS：工单、诊疗流程

一次任务闭环

文件夹触发新文件 / 新版本 / 定时批次
对象组包主件、附件、规则、历史版本
Agent 执行抽取、检索、比较、判断
证据化输出结论、原文、规则、置信度
人工关口确认、驳回、补件、覆盖
动作与回存报告、任务、API、审计日志

三种可合作产品形态

P0 · 首期

文件夹 Agent 任务中心

在云盘内选择文件包，一键执行初审、比对或检查，结果回到同一目录。

云盘主导体验 · 专业能力按任务调用
P1 · 联合方案

专业 Agent 连接器

合思、iTerms、CRM 或 MES 读取授权文件，专业处理后把报告与状态回写。

双方联合交付 · 适合已有系统客户
P2 · 独立产品

垂直 Agent 工作台

面向项目交付、制度治理等跨系统场景，以云盘作为默认知识与证据底座。

独立定价 · 需要明确预算人与高频任务

09 / 海外轻对表

只对齐产品形态，不展开海外市场史

海外样本用于校准“任务入口、专业数据、系统动作、商业模式”四件事。

10 / 验证与证据

不能约谈用户，也能先验证任务真伪

用行为、文件和采购证据替代主观访谈；所有结论保留“已知 / 厂商口径 / 研究判断”。

  1. 01 · 神秘客测试注册试用、提交同一任务，记录步骤、权限、人工关口与回存。
  2. 02 · 脱敏文件包横测合同、票据、SOP 各建金标，比较召回、引用、异常和总耗时。
  3. 03 · 公开案例反推从客户案例拆出触发、动作、交付物、ROI 与仍需人工的部分。
  4. 04 · 异步用户信号问卷、社群、工单、评论区，只问最近一次真实任务与替代方案。
  5. 05 · 采购 / JD 证据招标文件、岗位描述、实施商资料验证预算、系统栈与交付周期。
  6. 06 · 渠道侧访谈实施商、代理商、顾问更容易说明价格、失败原因与续费条件。

四道决策门

G1 · 委托意愿用户愿不愿交给 Agent？看真实文件上传率、任务启动率、敏感权限接受度
G2 · 结果可信能否快速复核？看原文引用准确率、规则命中率、人工推翻率
G3 · 效率成立真的减少总工时？看端到端耗时，不只看模型生成时间
G4 · 预算归属谁为结果付费？看预算人、采购科目、增购意愿与部署成本

11 / 竞品 × 中国行业机会

从国内标杆到海外竞品：行业内容流才是共同入口

融合国内产品调研与海外竞品研究：不把“有 AI”当作竞争力，而是比较谁能把专业知识、权限和业务动作连成可计价结果。

海外研究的共同结论：市场机会不在通用聊天，而在行业内容流转。Glean / Guru / 亿方云偏知识底座，Harvey / Hebbia 偏复杂文档与专业工作台，NotebookLM / Box / Sana 偏项目、内容或部门工作流；国内合思、金蝶、纷享销客、鼎捷等则证明业务系统入口和执行闭环决定落地。

产品形态 × 适合解决的问题

知识底座型 · Glean / Guru / 亿方云

连接、治理、权限化问答

适合企业搜索、制度问答、研发与客服知识复用。亿方云的差异不应是再做一个聊天框，而是把文件、版本、责任人、引用和审计做成可信上下文。

专业工作台型 · Harvey / Hebbia

复杂文档与高价专业任务

适合合同、尽调、投研、合规和研究 memo。与国内 iTerms、问财等对照，关键指标是每案处理时长、引用覆盖率、人工复核比例和审计准备时间。

项目 / 内容工作流型 · NotebookLM / Box / Sana

指定资料到结构化交付

适合课程、科研、项目交付、培训和部门服务。与国内项目、销售、制造 Agent 对照，关键是资料范围受控、输出可复核、结果能回写任务流。

国内业务系统型 · 合思 / 金蝶 / 纷享 / 鼎捷

对象、规则与动作闭环

财务、CRM、MES / ERP 已经提供业务对象和执行入口；云盘应作为文件证据与版本控制层接入，而不是替代专业系统。

12 / 知识资产 × Agent 路线

把云盘从文件夹升级为可执行的知识底座

融合海外知识资产地图与国内云盘合作判断：知识分类的终点不是找到文件，而是让 Agent 知道能用什么、该引用什么、是否允许写回、谁需要审批。

知识对象

从目录转向业务语义

统一识别制度 / 规章、组织 / 流程、项目 / 会议、产品 / 技术、合同 / 法务、销售 / 客户、行业 / 研究和个人工作资料。

治理属性

让内容可以被信任

每个知识对象记录来源系统、责任人、有效期、敏感等级、版本状态、适用范围、可引用字段和可执行动作。

角色化 Agent

同一知识，不同角色不同动作

  • 合同库：法务审查、采购条款对比、销售风险提示
  • 项目资料：项目洞察、工程技术问答、组合风险看板
  • 产品资料：售前方案、客服受控回答、竞品分析
  • 制度资料：员工问答、HR 工单、制度变更影响分析
产品控制点

分析和生成先于高风险执行

优先做带引用的结构化结果，再接审批、通知、任务分派和回写；写入、分享、删除、发通知默认人工确认并留下审计记录。
